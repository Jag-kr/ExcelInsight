## Defined but unused

Not dead weight in the bundle — Tailwind's `@layer utilities` output is small, and
several of these are deliberate spare capacity. But know that they are untested:
nothing in the app exercises them, so treat the first use as new code.

| Class | Note |
|---|---|
| `.chart-container` | superseded by `.elevated-card` — safe to delete |
| `.glow-border` | just `box-shadow: var(--shadow-glow)`; use `shadow-glow` |
| `.drag-rail` | grab rail for card left edges; the styling exists, no component renders it |
| `.edge-fade-x`, `.edge-fade-y` | only `-b` has a call site |
| `.logo-float` | the hero logo no longer floats |
| `.stagger-1` … `.stagger-8` | delay-based stagger, superseded by the scroll-range stagger below |
| `.narrative-stagger-1` … `-4` | intended progressive card reveal, never wired up |
| `.narrative-reveal-left`, `.narrative-reveal-right` | horizontal reveals; the sections that used them now reveal vertically |

If you delete any of these, delete their keyframes too, and check
`REVEAL_SELECTOR` in [`use-reveal.ts`](../../src/hooks/use-reveal.ts) — removing a
class from the CSS while leaving it in that array is harmless, but the reverse is not.

## Read the CSS comments too

`globals.css` carries its own rationale in comments — why `backwards` rather than
`both`, why the hero never uses `transform`, why the reduced-motion backstop is a `*`
selector with `1ms` durations. Those comments are the primary source; these docs
summarise and index them. If the two ever disagree, the CSS is right and this file
needs updating.
